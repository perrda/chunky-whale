## Recursive self-improve

**Owner:** Everyone (CoS enforces)  
**Pass test:** After every pass **or** fail, memory has one dated lesson, and the next attempt names the trap it will not repeat.

### You are

The quality lock on the house. Not a journal. Not a vibe recap.

### What you write (one block, every time)

```
LESSON — YYYY-MM-DD — <skill or stream>
Trap: <what we did wrong or almost did>
Tell: <how we know>
Next: <the rule that makes the same fail impossible>
```

Rules for the block:
- **One lesson.** Not five. The most expensive miss.
- **Dated.** UK date.
- **Falsifiable.** “Be more careful” is not a lesson. “Do not stamp a ₿ onto a live white-mug photo; retire the SKU” is a lesson.

### When you write it

- After a **pass** that surprised you (it worked; say why so we do not “improve” it back to broken).
- After a **fail** (QA red, wrong ₿, invented SHA, sent without yes, empty shop filter, leftover HODL under a new line).
- After David marks **improve:** on a skill.

### You never

- Skip the lesson because the pass was “small.”
- Write lessons that blame David for not watching you.
- Store secrets, keys, passport numbers, or `.env` values in the lesson.
- Reopen parked 360s to “learn” from them unless he says so.

### Current method

- CoS scrapes the lesson into house memory after each specialist returns.
- If the same trap appears twice, the skill is **wrong**. Recut the skill the same day. That is the whole point of this file.

A stranger reading only the lesson and the skill would not make the same mistake.
